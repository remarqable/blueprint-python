# 2.1.0

Action required: no

Everything in this version is an addition. No file moved and no setting changed
meaning. A project on 2.0.0 keeps working as it is; set
`blueprint_version: 2.1.0` and stop there if you want nothing new.

Two rules are new in `CLAUDE.md` and apply to code written from now on: with
`jobs: true`, `enqueue` is the last statement of the work that caused it (or
uses `commit=False`, step 2 below); and credentials, session tokens and user
content are never logged. On a project still recorded as 2.0.0 the audit
reports both as pending upgrades, which do not block.

New settings all default to what 2.0.0 did. A project that does not record them
has them off:

```yaml
realtime: false
ai: false
tenant_isolation: app
csp: relaxed
```

## What is new

| Addition | Where | Applies when |
|----------|-------|--------------|
| Observability | `patterns/core/observability.md` | every project |
| Data modeling | `patterns/core/data-modeling.md` | every project, for new tables |
| Realtime | `patterns/realtime.md` | `realtime: true` |
| AI | `patterns/ai.md` | `ai: true` (requires `jobs: true`) |
| Scale | `patterns/scale.md` | the dominant table is large |
| Row-Level Security | `patterns/tenancy.md` § Row-Level Security (opt-in) | `tenant_isolation: rls` |
| Strict CSP | `patterns/core/security.md` § Strict CSP (opt-in), `patterns/core/frontend.md` § Alpine with a Strict CSP (opt-in) | `csp: strict` |
| Record audit, extended | `patterns/core/audit.md` | `audit_logging: true` |
| Jobs, extended | `patterns/jobs.md` | `jobs: true` |

The two new core docs describe how to build from here on. They are not a list of
things an existing project has got wrong, and the audit reports anything that
exists only because of them as a pending upgrade, which does not block.

`make assets` now also vendors the Alpine focus plugin, which
`core/frontend.md` already used.

## Optional steps

Take any of these, in any order, or none. Each is independent.

### 1. Request and trace IDs on every log line

- **Find:** `create_app` does not call `register_observability`.
- **Change:** add `app/platform/obs.py` from
  [core/observability.md](../patterns/core/observability.md#correlation) and call
  `register_observability(app)` after `init_tenant(app)`. `logger.py` does not
  change.
- **Check:** a log line written inside a request carries `request_id` and
  `trace_id` without passing them.

### 2. Jobs: safe shutdown, recovery, queues and idempotency (ask before applying)

Adds four nullable or defaulted columns to `job` and one partial unique index,
in one migration. See
[jobs.md](../patterns/jobs.md#optional-columns-added-in-210).

- **Find:** the `Job` model has no `queue`, `priority`, `unique_key` or
  `trace_id` column.
- **Change:** add the columns and the migration, then take the 2.1.0 `enqueue`,
  `_claim_next`, `_recover_zombies` and worker loop from the chapter. Set
  `TimeoutStopSec` on the worker's systemd unit as
  [Graceful Shutdown](../patterns/jobs.md#graceful-shutdown) describes.
- **Before changing `enqueue`:** `queue`, `priority`, `unique_key` and `commit`
  become parameters, so they can no longer be payload keys. Search every
  `enqueue(` call for those names first.
- **Check:** the existing job tests pass; a worker sent SIGTERM mid-job finishes
  the job and exits 0.

Worth knowing even if you skip this step: the 2.0.0 `enqueue` commits. A job
enqueued in the middle of a piece of work is committed even if the rest of that
work fails. Calling `enqueue` last avoids it without any other change. See
[Transactional Enqueue](../patterns/jobs.md#transactional-enqueue).

### 3. Record audit: refuse a forged creator (`audit_logging: true`)

- **Find:** there is no `app/platform/audit.py`.
- **Change:** add it from [core/audit.md](../patterns/core/audit.md) and import
  it in `create_app`. Adjust its import of `AuditMixin` to wherever the project
  keeps the mixin.
- **Behaviour change:** assigning `created_by_id` on a stored row while a user
  is acting now raises. Scripts with no acting user can still backfill.
- **Check:** the tests in the chapter's Testing section pass.

With `jobs: true`, the chapter also describes a nullable `job.actor_id` so a job
credits the user who caused it. That is a second migration: ask before applying.

### 4. Row-Level Security under the application's scoping (ask before applying)

Only for `tenancy: shared` on PostgreSQL. This changes the database roles the
application connects as, adds a policy to every `OrgScoped` table and changes
how backups must run. Read
[tenancy.md § Row-Level Security](../patterns/tenancy.md#row-level-security-opt-in)
in full, apply it on staging against a copy of production data first, and set
`tenant_isolation: rls` only once the isolation tests pass there.

### 5. Strict Content-Security-Policy (ask before applying)

Every Alpine inline expression in every template is rewritten as a named
component, and inline scripts, styles and handlers are removed. Read
[core/security.md § Strict CSP](../patterns/core/security.md#strict-csp-opt-in).
Start with the policy in report-only mode, as that section describes, and set
`csp: strict` once the report is empty.

### 6. Record the version

- **Change:** set `blueprint_version: 2.1.0` in the project's root `CLAUDE.md`,
  and add the four new settings beside it with the values the project uses.
